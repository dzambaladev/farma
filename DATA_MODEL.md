# Модель данных Farma

## 1. Не путать уровни идентичности

Бытовое слово «препарат» может обозначать несколько разных сущностей:

1. **Ingredient** — действующее вещество или комбинация веществ.
2. **Brand / TradeName** — бренд или торговое наименование.
3. **DrugProduct** — конкретный продукт с составом, дозировкой и лекарственной формой.
4. **Package** — количество единиц, объём и тип упаковки.
5. **Registration** — сведения о государственной регистрации продукта.

Это не позволяет случайно объединить разные дозировки, формы выпуска или упаковки в одну запись.

## 2. Сущности

### Ingredient
- id — стабильный внутренний идентификатор;
- name — предпочтительное международное/официальное наименование;
- synonyms[] — подтверждённые синонимы;
- source_refs[] — источники.

### Brand
- id;
- name;
- normalized_name;
- owner_id — при наличии подтверждённых данных;
- source_refs[].

Бренд не обязательно совпадает с производителем конкретной упаковки.

### Manufacturer
- id;
- name;
- country — если подтверждено;
- source_refs[].

Позднее при необходимости разделяются производитель, заявитель регистрации, владелец бренда и площадка производства.

### DrugProduct
Конкретный вариант лекарственного продукта:
- id;
- brand_id — nullable;
- ingredients[] — ссылки на Ingredient с ролью и количеством;
- strength — структурированная дозировка/концентрация;
- dosage_form — форма из контролируемого справочника;
- route — путь введения, если подтверждён;
- manufacturer_id — nullable, с явным указанием роли;
- registration_ids[];
- source_refs[];
- status — статус записи в каталоге, не клиническая рекомендация.

### Package
- id;
- drug_product_id;
- quantity — число единиц;
- unit — единица измерения;
- package_description;
- barcode — nullable;
- source_refs[].

Один DrugProduct может иметь несколько вариантов упаковки.

### Registration
- id;
- country;
- registration_number;
- registered_name;
- holder;
- valid_from / valid_to — если доступны;
- status;
- source_refs[].

Регистрационный статус сопровождается источником и датой проверки. Его нельзя выводить из наличия записи в стороннем каталоге.

### Source
- id;
- publisher;
- title;
- url;
- source_type — например, государственный реестр, инструкция, производитель;
- published_at — nullable;
- accessed_at;
- supports[] — какие утверждения/поля источник подтверждает;
- notes.

Для важных полей желательно хранить происхождение на уровне отдельного утверждения, а не только общую ссылку на страницу.

## 3. Связи

- Ingredient ↔ DrugProduct: многие-ко-многим; у связи есть роль и количество.
- Brand → DrugProduct: один бренд может иметь несколько вариантов продукта.
- Manufacturer → DrugProduct: связь может быть неоднозначной; роль должна быть явной.
- DrugProduct → Package: один-ко-многим.
- DrugProduct → Registration: один-ко-многим или многие-ко-многим в зависимости от реестровой модели.
- Source → сущности/утверждения: один источник может подтверждать несколько сущностей и полей.

## 4. Пример условной записи

Пример иллюстративный, не описывает реальный препарат и не является медицинской информацией.

    {
      "id": "drugproduct_example_001",
      "brand_id": "brand_example",
      "ingredients": [
        {
          "ingredient_id": "ingredient_example",
          "role": "active",
          "strength": {"value": 100, "unit": "mg"}
        }
      ],
      "dosage_form": "tablet",
      "route": "oral",
      "package_ids": ["package_example_001"],
      "source_refs": ["source_example_001"]
    }

## 5. Правила качества данных

- Не объединять записи только по совпадению названия.
- Дозировка и лекарственная форма — часть идентичности DrugProduct.
- Упаковка — отдельный уровень, не часть свободного текстового названия.
- Комбинированный препарат содержит несколько Ingredient.
- Неизвестные значения хранить как null/отсутствующие, не подставлять предположения.
- Синонимы и транслитерации хранить отдельно от официального названия.
- Сохранять исходное написание источника наряду с нормализованным значением.
- Изменение регистрационного статуса фиксировать с датой проверки и источником.

## 6. Ограничение модели

Модель описывает идентичность продукта и опубликованные сведения о нём. Она сама по себе не доказывает терапевтическую эквивалентность, взаимозаменяемость или пригодность препарата конкретному человеку.
