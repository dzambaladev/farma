# Дорожная карта Farma

План разбит на короткие этапы. Каждый этап должен давать проверяемый результат и не создавать обязательства немедленно масштабировать проект.

## Этап 0. Зафиксировать рамки
- [x] Создать архитектурные документы.
- [ ] Утвердить назначение MVP.
- [ ] Утвердить языковую стратегию.
- [ ] Проверить название проекта и доменную стратегию на юридические и брендовые риски.

**Результат:** понятные границы продукта и отсутствие преждевременных технических решений.

## Этап 1. Проверить модель на одном примере
- [ ] Выбрать один реальный препарат для моделирования.
- [ ] Найти первичные и официальные источники.
- [ ] Заполнить Ingredient, Brand, DrugProduct, Package и Registration, где применимо.
- [ ] Проверить различия между дозировкой, формой и упаковкой.
- [ ] Зафиксировать неизвестные поля и конфликты источников.

**Критерий завершения:** одна запись прослеживается до источников, её идентичность не вызывает неоднозначности.

## Этап 2. Минимальный технический прототип
- [ ] Выбрать генератор статического сайта.
- [ ] Подготовить структуру репозитория.
- [ ] Реализовать загрузку и валидацию данных.
- [ ] Сгенерировать одну страницу препарата.
- [ ] Проверить страницу без выполнения JavaScript.

**Критерий завершения:** чистая сборка воспроизводится, страница содержит корректные данные и источники.

## Этап 3. Публикация
- [ ] Подключить репозиторий к Netlify.
- [ ] Настроить домен после отдельной проверки бренда и прав.
- [ ] Настроить HTTPS, redirects, canonical, robots и sitemap.
- [ ] Проверить мобильную версию и технические ошибки.

**Критерий завершения:** публичная страница доступна по постоянному URL и корректно читается роботами.

## Этап 4. Ограниченный каталог
- [ ] Добавить небольшую согласованную группу препаратов.
- [ ] Проверить поиск по названию и действующему веществу.
- [ ] Проверить внутренние связи и отсутствие дублей.
- [ ] Оценить, какие типы страниц действительно полезны.

**Критерий завершения:** пользователь может найти и правильно идентифицировать препарат из тестового набора.

## Этап 5. Наблюдение и улучшение
- [ ] Подключить Search Console и аналитику с минимально необходимым сбором данных.
- [ ] Проверять индексацию, ошибки и запросы.
- [ ] Улучшать качество данных и структуру страниц по результатам наблюдений.
- [ ] Только после этого решать, расширять ли каталог и добавлять ли функции.

## Вне MVP

Аптечные цены и наличие, коммерческие интеграции, личные кабинеты, отзывы, рекомендации и автоматический подбор аналогов рассматриваются отдельно. Для них потребуются самостоятельные источники данных, правовая оценка и дополнительные требования к качеству и безопасности.

## Принцип темпа

Нет необходимости проходить этапы быстро или параллельно. Проект должен оставаться небольшим и управляемым. Если обнаруживается фундаментальная ошибка модели, лучше остановиться и исправить её до расширения каталога.
